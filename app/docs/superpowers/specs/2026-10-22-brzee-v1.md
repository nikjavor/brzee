### Agreed timing policy

All ages below are effective ages: transmitted sample age plus local monotonic elapsed time.

| Condition | Initial limit / behavior |
| --- | --- |
| RPM age | Fresh below 500 ms; begin fading when it reaches 500 ms. |
| Pedal D or relative pedal age | Fresh below 750 ms; otherwise blend into RPM-only mode. |
| Pedal E or F age | Fresh below 2,000 ms; otherwise blend into RPM-only mode. |
| Whole stream | Stale at 1,000 ms without a complete snapshot, independently of notification arrival. |
| Assembly/sequence history | Reset after 1,000 ms without any notification; also reset on each new connection. |
| Sound fade / load transition | Approximately 200 ms, subject to listening and device validation. |

These are explicitly accepted starting limits, not assertions about every ECU's performance. Changes made after measurement must be recorded with their reason.

An explicit app force-quit ends the active session. A new launch starts muted; background support does not imply automatic audio startup after process termination.

## Screens and interaction

1. Connection: BRZEE branding and a large circular Connect control. Expose Bluetooth off/unauthorized/unavailable, scanning, selecting among multiple devices, connecting, subscribing, waiting for data, timeout, and retry states. Allow cancellation.
2. Dashboard: numeric speed in km/h centered inside the circle; segmented F1-inspired RPM arc and numeric rpm above; coolant left; accelerator pedal right; derived torque in Nm below. Include explicit labels/units, accessible sound enable/mute and volume, and compact connection/data freshness status.
3. Sound/profile sheet: list the working 911 GT3 RS profile, with no unavailable profiles presented as playable. Keep the model extensible. Provide a small settings/calibration sheet for source information, calibration, coolant display settings, and Reset vehicle learning.

A Bluetooth connection/subscription may lead to a waiting dashboard, but live status requires a complete valid v1 snapshot. Invalid, individually expired, stale-stream, and disconnected dashboard readings show unavailable rather than fabricated zeroes. Signed temperatures and torque remain signed; torque uses BLE ID 34.

Use safe areas, scalable text, readable contrast, large touch targets, screen-reader labels, and reduced-motion support. Segment fills and their labels must remain understandable without color alone. Gauge smoothing never changes the underlying numeric model or freshness.

An explicitly entered, persistently labeled Demo mode may use replay notifications through the production assembler/model. It must not connect to hardware or overwrite real vehicle learning. Sound enable remains explicit in Demo mode.

## BLE and telemetry contract

- Service f023e430-7ac9-4f6d-a40a-5a43b9181a01; notify-only characteristic f023e430-7ac9-4f6d-a40a-5a43b9181a02.
- Use the BLE library's subscription API to enable the standard CCCD. There are no telemetry read/write requests, audio-upload commands, or vehicle-control commands.
- One connected phone. No pairing, bonding, or encryption requirement. Subscription triggers a complete snapshot, followed by approximately 100-ms snapshots.
- Android may request MTU 247; correctness cannot depend on the result. iOS negotiates its own MTU. Support MTUs 23, 185, and 247, including records crossing fragments.
- Each notification has a five-byte header; the complete body is exactly 219 bytes with 35 fixed-order signed int32 values, validity bits, and uint16 ages. All multibyte values are little-endian.
- Enforce the complete receiver contract: version/count/index/size validation, ordered equal-capacity fragments, modular sequence comparison, expected gaps, wraparound, duplicates, assembly replacement/discard, reserved validity bits, and separate inactivity/stream timers.
- Atomically replace complete snapshots, retaining controller uptime and phone monotonic receipt time. Decode every record, not just displayed signals. Preserve raw signed values, validity, wire age, and the lower-bound meaning of saturated age 65535.
- The v1 validity bit cannot explain why a reading is unavailable. Expose availability honestly without inventing an unsupported-PID or hardware-failure diagnosis.
- Per-signal freshness is independent of the approximate 10-Hz BLE stream. Receiving the same old sample in a new snapshot does not refresh it.

### Proposed implementation defaults for plan review

The following are engineering choices proposed by the plan, not additional facts supplied by the user or protocol:

- Expand the working ceiling in 500-rpm increments, confirmed by three distinct fresh RPM samples above the old ceiling; repeated notifications of one sample do not count. Never shrink it automatically.
- Glide the mapping ceiling over about 1 second when it increases. Calibration and reset use controlled transitions.
- Begin with an explicitly estimated 800-rpm idle mapping reference. Offer Set idle using a stable stationary observation; do not label this default as another car's measured idle.
- Prefer a consistently fresh relative pedal (ID 19), then D (16), then E/F (17/18). Observe candidates for up to 2 seconds. If none exists, allow the first later fresh channel to be selected. Once selected, keep it fixed for that connection and enter RPM-only mode if it becomes unusable. Re-evaluate on reconnect.
- Until calibration exists, label pedal values as raw sensor percent; use a bounded raw-percent load blend. Only explicit released/full-travel capture establishes calibrated travel endpoints. Observing a partial press does not establish full travel.
- A user calibration belongs to its signal ID; never apply one channel's endpoints to another. Persist calibration and idle/ceiling estimates in one versioned current-vehicle record. Moving BRZEE to another car requires using reset.
- Use a configurable 0.25 load blend for RPM-only sound. This is an audio mix parameter, not estimated accelerator position.
- Display freshness limits: RPM/pedal as above, speed 1,500 ms, coolant and torque 5,000 ms, with the stream limit overriding all. Initial coolant display range -40 to 150 degrees Celsius; warning bands disabled until configured.
- Reset fades/mutes sound, clears learned ceiling/idle/pedal information, and returns the ceiling to 5,000 rpm. Keep ordinary profile/volume preferences separate.

## Agreed technology and boundaries

React Native and TypeScript using Expo development builds, with react-native-ble-plx and react-native-audio-api as the first native-library choices. Validate their exact version combination and background behavior before UI polish.

Keep BLE transport, assembly/decoding, telemetry/freshness, vehicle learning, audio control/rendering, persistence, and UI independently testable. Use a single authoritative telemetry state and a single runtime coordinator; React components consume selectors and issue user intents.

Use local builds and local persistence. Accounts, cloud services, maps, trips, firmware changes, store publishing, and real-time synthesized fallback audio are outside v1. EAS/TestFlight distribution is optional and is not implied by installing the Expo development-client skill.
